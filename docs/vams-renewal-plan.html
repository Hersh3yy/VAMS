Where VAMS stands

honest baseline
from the review

VAMS works and is deployed, but it carries the marks of fast MVP growth and a half-finished "refactor phase 1": a base-class/service layer the main entity mostly bypasses, duplicated media code, a plaintext API-key scheme, a permissive CORS policy, and a test suite that only recently came back to life. None of it is dramatic; all of it wants tidying before it takes public, tiered traffic. This plan is deliberately conservative — the running system must keep working, with a small migration only where it genuinely helps.

Tracks

6 tracks · session-sized items
ordered within a track

Order across tracks: A underpins everything (you cannot safely refactor without a green suite). B (security) and C (correctness) can interleave. D (tiers) builds on B. E (Coolify) can start now and lands the infra fixes A and B need. F (UX) runs alongside once the API is stable.

A

Test suite & CI — a floor under every later change

start here
  1. Env-shadow fix doneThe container bakes APP_ENV=local, which shadowed phpunit's testing everywhere → CSRF never skipped → 419 on every web test. tests/bootstrap.php forces the env in-process. 76 → 168 passing.
  2. Install gd in the imageThe 25 remaining failures are all LogicException in media-upload tests — ImageService's WebP/GD code hits a missing extension (the warning on every artisan call). Add gd to the Dockerfile; stub Storage::fake() where tests still touch disk.25 red
  3. CI that stays freeThis project earns nothing, so CI must cost nothing. GitHub Actions' free tier covers a public repo outright; for a private one, a Postgres/sqlite job stays well inside the free minutes. Coolify can also run the test step on deploy. Steps: composer install, php artisan test, Pint + PHPStan. Fail the build on red; the suite is now trustworthy enough to gate merges.
  4. Delete dead & duplicate codeRemove Api/MediaController (routes commented), MediaService (wrong disk), the media-record throw-stubs; the review lists them with line numbers.
  5. Update packages, and adopt ones that pull their weightRun composer outdated and npm outdated; take the Laravel 12 point releases and security patches first. Then look for packages that remove hand-rolled code: laravel/pint + larastan/larastan (lint/static analysis, free), spatie/laravel-permission (replaces the ad-hoc entry_type_permissions JSON and pre-wires the future tiers), spatie/laravel-backup (DB + Spaces backups for Coolify), spatie/laravel-medialibrary (could absorb much of the 497-line ImageService). Adopt only where it deletes more than it adds.
B

Security — before public / tiered traffic

after A1 · before launch
  1. Hash API keysKeys are stored plaintext and matched with a plain where, column unindexed (ValidateApiKey.php:28). Store hash('sha256',$key), look up by hash, unique index, show the raw key once. Migration re-issues existing keys.serious
  2. Add & register EntryPolicyEntry media upload gates on Gate::allows('update',$entry) but no policy exists → it always denies (MediaUploadController.php:246). Add the owner check so entry uploads work at all.critical
  3. Lock down CORSconfig/cors.php pairs '*' with supports_credentials — pin the real frontend origins (bemgijzel, the Image Colors app, admin).serious
  4. Mass-assignment & existence leaksDrop user_id from Entry::$fillable; return 404 (not 403) when an owned entry's type isn't permitted; audit the other models.
  5. Secrets & rate limitsMove all secrets to Coolify env (no committed keys); keep the 60/min API throttle, add per-key limits; review Telescope/Pulse exposure in production.
C

Core-flow correctness & patterns

after A · interleaves with B
  1. Fix paginated API 500successPaginated calls ->items()->map(), but items() is a plain array — any ?per_page= request throws (BaseApiController.php:49). collect(...) it; add a test that hits the paginated path.serious
  2. Bound reads, transact reorderAlways paginate (floor per_page at 1); wrap reorder()'s N updates in a transaction or one CASE.
  3. Resolve the base-class Refused BequestEither make BaseEntityService/BaseEntityController genuine templates the Entry path uses, or collapse them — today Entry overrides most of both and the base checks a non-existent published property. Pick one; don't keep a half-inherited hierarchy.
  4. Content-validation depthDecide the contract per field type: recurse for nested object/repeatable, or document that json is the passthrough for deep shapes (it is). Stop silently dropping unenumerated keys.
  5. Value objects for status/idsIntroduce a Status enum (draft/published) and stop scattering in:draft,published; small win against Primitive Obsession.
D

Account tiers — think, don't build (yet)

later · not on the critical path
  1. This is a product question before a code oneHiren isn't charging anyone and there's no marketing plan yet, so building tier enforcement now would be code ahead of a decision. Park it. Today's model (per-user is_admin, is_approved, entry_type_permissions JSON) is enough for the current handful of users.
  2. What to actually do now: keep the door open, cheaplyOne thing is worth doing early because it's nearly free and avoids a painful retrofit: put permissions behind a real package (spatie/laravel-permission, track A) instead of the ad-hoc JSON column. Tiers, when they come, are then "a role with limits" rather than a new system.
  3. When it's time: the questions to answer firstWho pays and for what (storage? API volume? seats? entry-type count?); free vs paid boundary; and a marketing/positioning plan. Only then does the tier column, quota enforcement (402/429), and billing become a build. Revisit as its own planning session.
E

DigitalOcean → Coolify

in flight · lands infra fixes
  1. Reproducible imageDockerfile with gd and the PHP extensions the app needs, pinned versions; the local docker-compose.yml is gitignored, so Coolify builds from the Dockerfile — make that the source of truth.
  2. Domain + SSL on CoolifyThis has to work before cutover: point the domain's DNS at the Coolify host, let Coolify issue the Let's Encrypt certificate (its built-in Traefik does this), verify auto-renewal, and force HTTPS. Set APP_URL and the Sanctum stateful domains to the real host so cookies and CORS line up.
  3. Env & secrets in CoolifyMove the DO env into Coolify's secret store; APP_ENV=production there, no secrets in git. Set the Spaces keys, and update the bucket CORS to allow the new origins (this is also on the security list).
  4. Move the data with a script, not a heavy migrationThere are only a few hundred entities/entries total, so this isn't a big-data migration. A one-off script reads from the DO Postgres and writes to the Coolify Postgres (a pg_dump | pg_restore for a clean cutover, or a small Artisan command that streams table-by-table and can be re-run to catch late writes). Spaces objects don't move — both hosts read the same bucket. Rehearse once against a throwaway target, then do it for real during a short read-only window.
  5. Backups (DO handled these for you)DO's managed Postgres did automatic backups; Coolify won't unless you set it up. Schedule nightly Postgres dumps (Coolify has a backup feature, or spatie/laravel-backup to also capture Spaces), keep a rolling retention, and test a restore once — an untested backup isn't a backup.
  6. Safe deploys: health check + rollbackWire /up to Coolify's health check so a broken boot is caught before traffic shifts. Coolify keeps previous images, so enable "roll back to the last good deploy on failure" (its lighter-weight stand-in for full blue-green). Confirm the one-click revert actually works before you rely on it.
  7. Observability & prod hygieneDecide Telescope/Pulse on or off in production (they can leak internals); keep logs somewhere you can read them; a basic uptime ping on the domain.
F

UI/UX audit & improvements

after the API stabilises
  1. Heuristic + accessibility auditWalk the admin and album/entry flows (Inertia + Vue): keyboard, focus, labels, contrast, error states, empty states. Record findings like the code review — severity + evidence.
  2. The CSRF-retry smellThere is a client-side CSRF-token retry loop (useCsrfToken, a whole CsrfTokenRetryTest) — a symptom of session/token friction. Fix the cause (token lifecycle) rather than retrying around it.
  3. Entry-type & media authoring UXThe entry-type builder and image-collection/upload flows are where users spend time — smooth the field editor (now incl. json), upload progress, and reorder.
  4. Design tokens & consistencyA shared token set for the admin theme (the per-user album_display_settings colours hint at a design-system need) and a component pass.
